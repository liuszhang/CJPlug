## 1. 现状（调研结论）

| 项 | 实测 |
|---|---|
| CJPlug 带 `@page` 的 razor | **160** 个（其中 `modules/Integrations` 下 120 个是插头 UI，承载于插头配置抽屉，不做页面级授权） |
| 非插头页面 | **39** 个 |
| 带 `[Authorize]` | **0** |
| 带 `[ModuleAccess]` | **0** |
| 菜单项 `AccessKey` | 仅 `plug-shell` / 登录按钮 / `module-admin` 等少数，业务菜单**全未填** |

⇒ 现状语义：**登录后所有页面均可访问，且缺 `[Authorize]` 的页面匿名也能渲染**（服务端 `UseWhen(NeedsIdentity, UseAuthorization)` 只在端点带授权元数据时才会拦）。

### 1.1 机制链（已具备，无需新建）

```
页面 @attribute [ModuleAccess(key, defaultRoles)]
        │
        ▼
FrameworkRoutes.razor → ModuleAccessRouteView（CJCore.Framework.UI）
        │  解析优先级（高→低）：
        │  ① 宿主 ModuleAccessOptions.Roles[key]
        │  ② 模块声明 IModuleAccessDeclaration（代码内白名单）
        │  ③ 页面特性 DefaultRoles
        │  ④ 全局兜底
        │  ⑤ 仅要求登录
        ▼
未授权 → <NotAuthorized> → RedirectToLogin
```

- 页面**必须**同时填菜单 `AccessKey = key`，否则侧栏可见性与页面准入两套口径会漂移（菜单看不见但 URL 能进）。
- 模块需注册 `IModuleAccessDeclaration`，否则该键在**权限矩阵页**（`/admin/role-permissions`）里不出现 ⇒ 现场无法改角色。

### 1.2 键位规范（沿用既有 Q8 定案，不新造体系）

`ModuleId` 已是 `plug-<模块>`（P6 模块启停口径），**直接复用为访问键**；子功能用 `:<子域>` 后缀（对齐 CJCore `system-config:read|write`）。

## 2. 第一批范围（6 个核心模块）

筛选三原则：① 敏感度（改密钥 / 授权 / 控制设备）；② P5.6 后仍存活（排除 Auth/Audit/UserManage/Login 四模块）；③ 有独立菜单入口。

| # | 模块 | 访问键 | 页面 | P5.6 后存活 | 敏感点 |
|---|---|---|---|---|---|
| 1 | LLM 配置 | `plug-llm-config` | `/LlmConfig` | ✔ | 供应商 API Key、模型端点 |
| 2 | 许可证 | `plug-license` | `/LicenseManage` | ✔ | 授权码/机器绑定 |
| 3 | MCP 工具管理 | `plug-mcptools` | `/MCPToolManage` | ✔ | 可注册外部工具端点 |
| 4 | 插头管理（工具动作） | `plug-tool-action` | `/TAS` | ✔ | 定义插头可执行动作 |
| 5 | AI API Keys | `plug-ai:keys` | `/AIAgent` | ✔ | 平台对外 API 凭据 |
| 6 | 远程桌面 | `plug-guacamole` | `/remote/{ip}`、`/remote/vnc/{ip}`、`/remote/ssh/{ip}`、`/remote/capture/{ip}`、`/guacamole/{ip}` | ✔ | **可直接操作工位机桌面** |

**默认角色 `system_admin`（全 6 项）。** 理由：当前种子只有三员 4 账号，业务侧尚无"运维/操作员"角色划分；先按最小授权，现场要放宽可在 `/admin/role-permissions` 改矩阵（这正是注册 `IModuleAccessDeclaration` 的目的）。

### 2.1 为什么不选它们（记录判断，防反复）

| 候选 | 排除理由 |
|---|---|
| `/SystemManage`、`/AuthManage`、`/AuditManage`、`/UserManageList`、`/RoleManageList`、`/DepartmentManage` | 属 P5.6 下线模块（UserManage/Auth/Audit），标了也要删 |
| `/admin/modules`、`/system-config` | CJCore 自带页面，已由 `AdminRoles`/`AccessRoles` 控制（P5.1 已配 `system_admin`） |
| `/three-role/system|auth|audit` | 三员页面自带 `[ModuleAccess("three-admin:*")]`，不重复标 |
| `/debug/plug-agent` | 内部调试台，第二批随"工具面"一起处理（与 P5.8 API 键同批更顺） |
| `/AskAI`、`/ChatTest` | 业务使用页，锁死会挡住普通用户；只锁同模块的 `ApiKeys.razor` |
| `/process/{...}/execute/{...}`、`/stlviewer` | **独立执行/嵌入页**，可能被工位机或插头 iframe 直接打开；加授权会破坏执行链路（第二批单独评估，需带 AllowAnonymous 白名单） |
| `/login`、`/Error` | 必须匿名 |
| `modules/Integrations` 下 120 个插头页 | 承载于插头配置抽屉（`/TAS` 内），入口已被第 4 项锁住 |

## 3. 改动三件套（每个模块 3 处，共 18 处）

### 3.1 页面（1 处或 N 处）

```razor
@page "/LlmConfig"
@attribute [ModuleAccess("plug-llm-config", "system_admin")]
```

需要 `_Imports.razor` 有 `@using CJCore.Framework.Abstractions`（缺则补）。

### 3.2 菜单（1 处）

```csharp
new() { Icon = ..., Href = "/LlmConfig", Text = "LLM 配置", GroupName = "管理",
        AccessKey = "plug-llm-config" }
```

### 3.3 模块声明（1 处，`ServiceCollectionExtensions.cs`）

```csharp
services.AddSingleton<IModuleAccessDeclaration>(
    new ModuleAccessDeclaration("plug-llm-config", ["system_admin"], "LLM 配置"));
```

> ⚠ 用 `AddSingleton` 而非 `TryAddEnumerable`：与 CJCore `SystemConfigModuleExtensions` 同款；同一键重复注册会在矩阵里出现两行。

实现细节：
- 页面统一用**全限定名** `@attribute [CJCore.Framework.Abstractions.ModuleAccess("key","system_admin")]` —— 不依赖各模块 `_Imports.razor`（4 个模块缺该 using、Guacamole 无 `_Imports.razor`），零侵入。
- 声明统一 `services.AddSingleton<IModuleAccessDeclaration>(new ModuleAccessDeclaration(key, ["system_admin"], "模块名"))`，与 CJCore `SystemConfigModuleExtensions` 同款。

### A.2 两个必须记住的机制事实

1. **`FallbackPermissionStrategyRouter` 丢掉页面特性默认角色**：它调 `_access.GetEffectiveRoles(key, moduleDefaultRoles: null)`，所以 `[ModuleAccess("x","role")]` 的第二个参数在这条链上**不生效**，只有"宿主配置 / 模块声明"能决定角色。本仓已装统一鉴权中心（`ConfiguredPermissionStrategyRouter` + `RoleDataMenuStrategy`），实际走的是 `AdminRoles` 硬保护 + `PM_RoleMenuPermissions` 白名单（**无记录 = 拒绝，Q7 严格模式**），declaration 主要作用是让矩阵页扫得到键。
2. **CJPlug 存在两套并行权限体系**：旧 `IFunctionPermissionProvider`（`Plug.View`/`Plug.Create` 等细粒度键，7 个模块已注册）与 CJCore 的 `ModuleAccess` 链**互不连通**，且旧体系全仓**只注册、无消费方**（grep 无读取点）。P5.5 只接 CJCore 链；旧体系列为第三批清理对象。
