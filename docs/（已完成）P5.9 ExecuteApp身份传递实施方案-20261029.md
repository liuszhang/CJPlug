# P5.9 ExecuteApp 身份传递实施方案（D-P5-7）

> 决策点：**D-P5-7**（P5 身份替换遗留缺口）
> 状态：已完成（2026-10-29 实测通过）
> 日期：2026-10-29
> 前置：P5.4 / P5.5 / P5.6 / P5.7 已完成

---

## 1. 问题

`CJ.Plug.ExecuteApp`（WPF + WebView2）是**独立进程**，通过 `Process.Start` 由服务端拉起，裸 URL 打开 `/process/{id}/execute`。

WebView2 是一个**空白的 cookie 容器**：
- 没有浏览器的 `CookieContainer`
- 没有任何 token 注入
- 于是 `[Authorize]` 页面在里面必然 302 到登录页

因此 P5.5 第二批**刻意**没有给 `/process/{id}/execute` 加鉴权，留下缺口：

| 缺口 | 后果 |
|---|---|
| 执行页匿名可达 | 任何人拿到 `plugDefinitionId` 就能打开执行界面、触发流程执行 |
| 无身份上下文 | 执行产生的审计日志拿不到操作人，"三员"审计链在此断掉 |

---

## 2. 关键约束（决定了方案形态）

| # | 约束 | 证据 |
|---|---|---|
| C1 | `BaseApiClient.httpClient` 是**裸 HttpClient**，`BaseAddress = GlobalData.MainApiServer`，**无任何认证头/Cookie** | `Core/CJ.Plug.Models/ApiClient/BaseApiClient.cs:11-21` |
| C2 | ⇒ 服务端调用 `/api/plug/launchStandalone` 时，端点**拿不到调用者身份**（既无 Cookie 也无 Bearer） | 同上 |
| C3 | `.ThreeRole.Auth` 是 ASP.NET Core 加密票据，**只有服务端能签发**，客户端无法伪造 | `CJCoreAuthEndpoints.cs:110` `SignInAsync` |
| C4 | `.ThreeRole.Token` 是 **非 HttpOnly** 的 AT 明文 cookie（CJCore D3 决策：电路恢复时 JS 要读） | `CJCoreAuthEndpoints.cs:126-131` |
| C5 | CJCore 已有**一次性换票码**：`CJCoreEmbedTicketStore.Issue(at)→code`（60 s / 单次 / 内存表），配 `/embed-cookie?code=&returnUrl=` 端点签 cookie 并 302 | `CJCoreEmbedTicketStore.cs`、`CJCoreAuthEndpoints.cs:186-228` |
| C6 | `returnUrl` 只接受站内相对路径（防开放重定向） | `CJCoreAuthEndpoints.cs:349-358` |

**C5 是决定性的**：CJCore 已经为"外部进程要把登录态搬进浏览器"这个场景做完了基础设施（CJWork 端同源嵌入在用）。不新造轮子。

## 3. 方案

### 3.1 数据流

```
[浏览器 Blazor 电路 /ProcessManageList]
   │ ① JS 读 .ThreeRole.Token（非 HttpOnly）→ AT
   ▼
MainApiClient.LaunchStandaloneAppAsync(defId, at)
   ▼
POST /api/plug/launchStandalone/{defId}   body { accessToken }
   ▼
[ApiServer · PlugExecuteApi]
   │ ② 空 AT → 401（堵匿名拉起进程的 DoS 入口）
   │ ③ CJCoreEmbedTicketStore.Issue(at) → code（60 s / 单次）
   │ ④ Process.Start(ExecuteApp.exe, "\"{baseUrl}\" \"{defId}\" --ticket={code}")
   ▼
[ExecuteApp · WebView2]
   │ ⑤ Navigate {baseUrl}/api/three-role/account/embed-cookie?code={code}&returnUrl=/process/{defId}/execute
   ▼
[CJCore 认证基座]
   │ ⑥ code → AT → SignInAsync(.ThreeRole.Auth) + 写 .ThreeRole.Token → 302 执行页
   ▼
[执行页]  ⑦ 带 Cookie 正常渲染，[Authorize] 通过；审计日志能拿到操作人
```

### 3.2 为什么不用「CookieManager 注入」

原始推荐 A 写的是"传 token → `CoreWebView2.CookieManager.CreateCookie` 注入 `.ThreeRole.Auth`"。
落地时否掉，原因：

| 问题 | 说明 |
|---|---|
| 注入不了 | `.ThreeRole.Auth` 是**加密票据**（C3），客户端根本无从构造合法值 |
| 硬编码耦合 | 得把 cookie 名、domain、path、Secure/SameSite 全在 WebView2 侧复制一遍，内核改一次就静默失效 |
| 已有正解 | `/embed-cookie` 一次导航全部搞定，且 `Secure`/`SameSite`/过期时间都由服务端按 `HttpContext` 正确判定 |

故保留 A 的**方向**（启动参数带凭据 + 页面加载前建立 cookie），把机制换成 CJCore 现成的换票码。

### 3.3 为什么用一次性码而不是直接传 AT

AT 有效期 15 分钟。若把 AT 写进 `Process.Start` 的**命令行**，任何本机进程都能用
`Get-CimInstance Win32_Process` / Process Explorer 读到，等于把一个 15 分钟有效的登录态广播给本机所有用户。

一次性码把"可被记录的字符串"压缩成 **60 秒、单次消费、192 位随机** 的短串（C5 设计意图，原话见
`CJCoreEmbedTicketStore` 类注释）。AT 全程只存在于服务端内存。

## 5. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 电路内 JS 读不到 AT（首帧 SSR / JS 未就绪） | 返回 null → 端点 401 → 前端 Snackbar 提示"登录态未就绪，请刷新后重试"，**不静默失败** |
| R2 | 页面停留超过 AT 有效期（15 min）后点启动 | 电路有定时续期 + 写回 `.ThreeRole.Token`；JS 读到的是最新 AT |
| R3 | 手工从命令行启动 ExecuteApp（无 `--ticket`） | 降级：直连执行页 → 302 登录页 → 人工登录后可用。**不阻断** |
| R4 | `launchStandalone` 端点被匿名刷 | 已改为**无 AT 即 401**，匿名无法触发 `Process.Start` |
| R5 | code 60 s 内被同机其它进程截获 | 需先拿到 code（命令行可见）+ 60 s 内完成导航；攻击面远小于 AT 明文。彻底方案是 D-P5-10 收窄监听 + 本机进程隔离 |
| R6 | `embed-cookie` 落在 ApiServer 还是 WebHost | 单进程同端口（5066），同一份 cookie 域，无跨端口问题 |

**实施中发现并顺手修掉的存量 bug**：`launchStandalone` 的 exe 路径推导用
`Path.Combine("..","..","..","CJ.Plug.ExecuteApp")` + `[Debug|Release]/net10.0-windows/`，
但 `BaseOutputPath` 是 `..\..\..\..\02.Publish\Services`（**不带项目名**），ExecuteApp 实际与 ApiServer 是
`Debug\net10.0` / `Debug\net10.0-windows` 同层兄弟目录 ⇒ 旧写法永远找不到 exe。
该端点此前从未被真实调用过故未暴露。已改为**候选路径探测**（同层兄弟 / 配置 AppPath / Services+配置 / 项目名布局四选一）。

**验证手段备忘**：
- WebView2 cookie 库位置：`02.Publish\Services\Debug\net10.0-windows\CJ.Plug.ExecuteApp.exe.WebView2\EBWebView\Default\Network\Cookies`
  （SQLite，进程活着时被锁 ⇒ `taskkill` 后 `shutil.copy2` 再读）。
- `.ThreeRole.Auth` 是 session cookie（未设 Expires）⇒ **不落 Cookies 库**（存在 WebView2 内存），库里只见 `.ThreeRole.Token` 属预期，不是缺陷。
- 换票链路的独立复现：`POST /api/three-role/account/embed-ticket`（Bearer AT）拿 code → `GET /embed-cookie?code=` 看 Set-Cookie 与 302。
