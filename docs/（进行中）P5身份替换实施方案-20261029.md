## 2. 关键证据（可复核）

### 2.1 密码算法不兼容（决定性）

```text
库中 admin.PasswordHash（84 字符 base64）→ 解码 61 字节
  marker = 0x01          → ASP.NET Identity v3 格式
  PRF    = 2             → HMACSHA512      ← 注意不是 SHA256
  iter   = 100000
  saltlen= 16            → salt = raw[13:29]
  subkey = 32 字节
用 sha512+123456+同盐同迭代重算 ⇒ 与库中子密钥完全相等 ✅
用 sha256 同样参数重算        ⇒ 不相等 ❌
```

内核实现 `CJCore.Framework.Api/Auth/Pbkdf2PasswordHasher.cs`：`Rfc2898DeriveBytes.Pbkdf2(..., HashAlgorithmName.SHA256, KeySize=32)`，`Verify` 里 `hash.Length != 32 → false`，**PRF 不可配**。

⇒ 结论：**TRA 原生 hasher 无法验证现有密码；但两边同为 PBKDF2 家族、同 key 长度，只是 PRF 不同。**

### 2.2 种子会自建账号（但受顺序约束）

`ThreeRoleAdminSeedDataProvider.cs:58` — `if (!await db.Set<SysUser>().AnyAsync(ct))` 才种：
`admin`(Id=1,Role=1)、`sysadmin`(2,1)、`autadmin`(3,3)、`audadmin`(4,2)；密码 `hasher.Hash(adminPwd/defaultPwd)`，`SaltIterations` 硬编码 **10000**。

⇒ 迁移脚本若先写 `TRA_SysUsers`，种子整体跳过，此时**必须**由脚本负责密码；若不迁移用户，种子会给出可用账号。

### 2.3 附带风险：TRA 默认密码策略与默认密码冲突

`TRA_Pwd_MinLength=8` + 要求大写/小写/数字，而缺省密码 `123456` 只有 6 位纯数字。`LoginAsync` **不校验策略**（仅 `RegisterAsync`/改密校验）⇒ 能登录，但**首次改密会被策略挡下**，现场会表现为「登进去了却改不了密码」。需在 P5 显式决策（放宽策略 or 用合规初始密码）。

### 2.4 与 P4 的兼容性（已确认无冲突）

| 项 | 结论 |
|---|---|
| 三员伞项目是否连带 Data UI 菜单 | **不会** — 它只引 `CJCore.Modules.Data.Api`（P4 踩过的坑不复现） |
| `ThreeRoleAdminModuleDbConfig` 与 P4 适配器 | 不冲突 — 它是内核原生 `IModuleDbConfig`，不进 CJPlug 的 `BusinessModuleDbConfigAdapter` |
| 表名 | TRA_* 20 张，与 CJPlug 的 `Users/Roles/Departments/...` 无重名 |
| `UserModuleDbConfig`（CJPlug 身份 7 表） | P5 期间可与 TRA_* 并存，5.7 时删除 |

### 2.5 已知遗留会撞上 P5

`K.10` 登记的第 1 条：登录后 circuit 内抛
`InvalidCastException: PlugTempAdminAuthStateProvider → Elsa.Studio.Login.Services.AccessTokenAccessor`。
说明 **Elsa Studio 内部假定 `AuthenticationStateProvider` 是它自己的实现**。P5 删掉临时 provider 换成 TRA 的之后，需要同步验证 Elsa Studio 页面（`/elsa/*`）的登录态，否则可能从「异常」变成「页面打不开」。

## 4. 决策点（逐个拍板，一次一个）

### D-P5-1　存量账号与密码怎么处理？　← **先拍这个**

| 选项 | 做法 | 旧密码可用 | 改动量 | 风险 |
|---|---|---|---|---|
| **A 重种** | **不迁移 `Users`**；靠三员种子自建 `admin/sysadmin/autadmin/audadmin`（密码走 `ThreeRoleAdmin:AdminPassword` 配置）；旧表留着不用 | ❌ 全部失效 | 最小（0 脚本） | 客户现场若有真实用户，**全员必须重设密码** |
| **B 迁移 + 产品侧兼容 hasher**（推荐） | 脚本把 `Users`→`TRA_SysUsers`（解析 Identity v3：salt/iterations/subkey 三列直填）；CJPlug 注册覆盖版 `IPasswordHasher`，`Verify` **先试 SHA256、失败再试 SHA512**，成功后按 SHA256 重算（惰性升级） | ✅ 原密码可登 | 脚本 ~120 行 + 兼容类 ~40 行 | 每次登录多算一次 PBKDF2（约 +60ms，可接受）；属"兼容层"，但**代码只在 CJPlug 侧，不污染内核** |
| **C 迁移 + 全量重设** | 用户行迁移，`PasswordHash` 留空；管理员登录后逐个重置 | ❌ | 脚本 ~100 行 | 迁移后**无人能登录**（种子因表非空而跳过）⇒ 必须额外写一个可登录的引导账号 |

**推荐 B**，理由：
1. 不污染内核（符合「共享内核 + 产品自定义」原则），靠 `AddScoped` 可覆盖特性实现；
2. 无需哨兵约定 —— 双算法回退即可，`iterations` 不改语义；
3. 客户内网环境下，"所有人重设密码"是运维事故，而 B 让迁移对用户不可见；
4. 数据量小，脚本风险本来就很低，值得为"零感知"多写 40 行。

**若你判断客户现场实际只有 admin 一个账号在用** → 选 A 更省事，且 P5 的可回滚性更好（不动用户数据）。

### B.2 验证项 2：登出 / 真撤销

**结论：JWT/refresh 通道真撤销 ✔；cookie 通道存在"票据自包含、无服务端会话绑定"的窗口期缺口（内核侧，登记新决策点 D-P5-6）；另发现两个旧入口残留假登出。**

| 实测（API 级，curl/node 直调） | 登出前 | 登出后重放 |
|---|---|---|
| `me` + Bearer（JWT 通道） | 200 | **401** ✔（`RevokeSessionAsync(jti)` 生效） |
| `refresh` + 旧 refreshToken | — | **401** ✔ |
| `me` + 仅 Cookie（`.ThreeRole.Auth` 8h 滑动票据） | 200 | **200** ✘ —— 票据自包含且 `OnValidatePrincipal` 不查会话 ⇒ 窗口期内重放有效 |
| logout 响应（**带 Bearer**） | — | `Set-Cookie: .ThreeRole.Auth=; expires=1970…` + `.ThreeRole.Token=; …` 两条删除头都发了 ✔（**登出端点本身正确**；node 首测"保留"是 header 小写化导致 includes 误判） |

**缺口语义**：电路内登出走 `PersonalCenterMenuItems.LogoutAsync → SignOutAsync`，服务端撤销 JWT/refresh，但 circuit 内 fetch 的 Set-Cookie **到不了浏览器**（基座注释明示"浏览器亲请求才落 cookie"）⇒ 浏览器 cookie 残留；且 cookie 票据无会话绑定，窃取/残留重放在 8h 滑动窗口内仍能通过 PolicyScheme（`me` 200）。Blazor 页面管道因会话态失效会 302，缺口仅暴露在直接调 API 的场景。
**修法方向（内核 CJCore，非本仓）**：cookie 票据加 jti + `OnValidatePrincipal` 查 `OA_Sessions`（与 JWT 同表），或 logout 端点同时撤销 cookie 票据的 jti。

**发现的两个旧入口残留（均为 LoginModule 遗产，P5.6 下线时自然消失）：**

1. **假登出按钮**：AppBar 的「欢迎：xxx ⎋」（`LoginState.razor`，由 `LoginModule.cs:30 AddAppBarItem<LoginState>` 挂载）。点击只清旧 localStorage + 跳 `/login`（P5 后该页已非登录页）——**不清三员 cookie、不撤销会话**。与绿色头像（`PersonalCenterUserMenu`，正确的登出入口）并存于 AppBar。
2. **"欢迎："后用户名空白**：`userName` 取自 `DomInteropService.GetCurrentUserName()`（旧 localStorage key），三员登录不写该 key ⇒ 恒空。随 LoginModule 下线消失，无需单修。
