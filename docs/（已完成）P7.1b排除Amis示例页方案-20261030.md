## 1. 问题：交付物自带 120 个匿名演示页

B 批次盘点"页面门控缺口"时，`@page` 统计给出 **152 处 / 151 个文件**，其中 **120 个文件全部落在
`src/modules/Integrations/CJ.Plug.AmisIntegration/Components/Pages/`** —— Amis 官网的演示页
（`/CRUD/Aside`、`/Form/Basic`、`/Event/EventAction` …），按一级目录分布：

| 目录 | 页数 |
|---|---|
| `Pages/Event/` | 38 |
| `Pages/Form/` | 25 |
| `Pages/CRUD/` | 25 |
| `Pages/Linkpage/` | 7 |
| `Pages/Tabs/` | 6 |
| `Pages/Services/` | 3 |
| `Pages/Page/` | 3 |
| `Pages/Dialog/` | 2 |
| `Pages/` 根散页（Audio/Chart/Code/Weather/Wideo/PdfViewer…） | 11 |

**为什么会暴露**：`CJ.Plug.AmisIntegration.csproj` 被 `CJ.Plug.PlugBaseCore.csproj:24` 引用，
Blazor 路由从程序集扫描 `@page`，于是这 120 个页面**自动全部注册进唯一宿主 `CJPlug.Server` 的路由表**，
且**无任何认证/门控**（无一页声明 `[ModuleAccess]`，多数未声明 `[Authorize]`）。
现场表现 = 打开 `http://<host>:5066/CRUD/Aside` 就能看到一个完整的 Amis 演示页。

对客户环境：**零功能价值，纯攻击面 + 纯体积**。

## 2. 为什么"构建期排除"而不是另外两条路

| 选项 | 做法 | 否决理由 |
|---|---|---|
| **A（选定）** | csproj 里 `Content Remove` + `RazorComponent Remove` 排除 `Components/Pages/**`，源码留仓库 | — |
| B | 给 120 页统一加 `[ModuleAccess("amis-demo")]` | 只是"上锁"，120 个页面连 js 资源照样打包进交付物；且 B-2 页面门控本来就要改这批文件，等于为演示页付维护成本 |
| C | 物理删除 `Components/Pages/` | 它是 Amis 各组件的**用法参照**（改 `Amis.razor` 渲染或排查 Amis 行为时要查），删了不可逆。构建期排除可一行恢复 |

## 3. 关键前提：业务侧不依赖 Pages（已取证）

排除会不会打断功能，取决于**有没有人引用 Pages 里的东西**。取证结果：

| 消费点 | 用的什么 | 是否在 Pages 下 |
|---|---|---|
| `Core/CJ.Plug.PlugBaseCore/PlugSettingDialogCore.razor:285` | `OpenComponent<Amis>` | 否（`Components/Amis.razor`） |
| `modules/.../CJ.Plug.GUIDesigner/GUIEditor.razor:60` | `<Amis JsonStringData>` | 否 |
| `modules/.../CJ.Plug.GUIDesigner/Widgets/BaseGuiItemWidget.razor:12` | `<Amis Data>` | 否 |
| `WebHost/CJ.Plug.MainPageContent/Shell/PlugHeadModule.cs:47-66` | `_content/CJ.Plug.AmisIntegration/**` 静态资源 + 内联 `amisLoad` | 否（`wwwroot/`，且脚本定义在**本仓**而非本项目） |

补充：全仓 `grep "AmisIntegration"` 共 6 个文件，其中 5 个只 `@using CJ.Plug.AmisIntegration.Components`
（即 `Amis.razor` 所在命名空间），**没有一处引用 `Components.Pages.*` 或 `Components.Layout.*`**。
`Components/Pages/` 下无 `.cs`、无 `@namespace` 覆写，纯 `.razor`。

> 也就是说：`Amis.razor` 只依赖 `Js.InvokeAsync("amisLoad", id, json)`，而 `amisLoad` 定义在
> `PlugHeadModule.cs:69` 的内联脚本里。**排除 Pages 对它零影响。**

## 4. 实现（唯一改动：`CJ.Plug.AmisIntegration.csproj`，+5 行生效逻辑）

```xml
<ItemGroup Condition="'$(IncludeAmisDemoPages)' != 'true'">
    <!-- .razor 在 Razor SDK 中同时挂在 Content 与 RazorComponent 两个 item 上，两处都要 Remove -->
    <Content Remove="Components\Pages\**\*.razor" />
    <RazorComponent Remove="Components\Pages\**\*.razor" />
</ItemGroup>
```

设计要点：

1. **双 item 移除**：只写 `Content Remove` 在部分 SDK 版本下仍会被 `RazorComponent` glob 捞回编译，
   两处都移除才干净（实测 `Components.Pages` 在 dll 里字符串命中为 0）。
2. **保留 `IncludeAmisDemoPages=true` 开关**：将来要查 Amis 用法或截演示图，
   `dotnet build -p:IncludeAmisDemoPages=true` 即临时编回来，**不必改文件**。
3. **只排 Pages，不动 Layout / wwwroot**：`Layout/NavMenu.razor` 与 `wwwroot/test.html`、`wwwroot/photo/`
   是演示资源，但它们**不产生路由**，不在本次拍板范围（见 §6 遗留）。

### 5.2 路由消失（19 条抽样，全部 `200` + 正文「404 - 页面未找到」）

返回 **200 + HTML「404 - 页面未找到」**。故判活**必须断言正文**（与 `/health` 假 200 同源）。
最干净的对照是**未登录**状态：

| 请求（未登录） | 状态码 | 含义 |

| `GET /CRUD/Aside` | `200` | 路由不存在 → 落 catch-all（无认证要求） |
| `GET /KnowledgeManage` | `302 → /three-role/login?ReturnUrl=…` | 路由存在 → 触发 `[Authorize]` |
